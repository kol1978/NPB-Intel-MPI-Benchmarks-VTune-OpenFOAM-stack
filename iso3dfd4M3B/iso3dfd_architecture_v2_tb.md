# ============================================================================
#       АРХИТЕКТУРА iso3dfd V2: 4 РЕЖИМА × 3 БЛОКА + L3 TEMPORAL BLOCKING
# ============================================================================
#
# Проект: iso3dfd4M3B (4 MODES, 3 BLOCKS)
# Железо: 2× Intel Xeon X5675 (Westmere, 6 ядер/сокет, 12 физических всего)
#         2 NUMA-узла, DDR3-1333, 12 МБ L3/сокет
# Компилятор: icpx (Intel oneAPI 2026.1)
# Флаги: -O3 -fiopenmp -xSSE4.2
# MPI: Intel MPI 2021.18
# OpenMP: 5.1
# Стандарт: C++14
#
# Терминология (согласованная):
#
# Loop tiling (тайлинг, разбиение циклов на плитки; также известен как cache
# blocking) — оптимизирующее преобразование, при котором итерационное
# пространство цикла разбивается на небольшие блоки (tiles), целиком
# помещающиеся в кэш. Цель — максимизация переиспользования данных до их
# вытеснения из кэша.
#
# Иерархия тайлинга в коде:
#
#   Уровень        Термин                  Что делает
#   ─────────────────────────────────────────────────────────────
#   L3-блок        Spatial tiling          Разбиение по (X,Y,Z) — блок 64×64×b3
#   Волновой фронт  Temporal tiling         Разбиение по времени — N=4–8 шагов
#   L2-микроблок   Nested spatial tiling   Вложенное разбиение по Y — b2_l2=48
#   L1-цикл        Векторизация            Цикл по X, векторизуется icpx
#
# Источники терминологии:
#   [1] IEEE Trans. on Computers, 1999 — "loop blocking (tiling)"
#   [2] Springer, Int. J. Parallel Programming, 2022 — "loop tiling"
#   [3] Intel Optimization Reference Manual, #248966, разделы 8.6.1, 11.6.1
#   [4] Intel YASK tutorial — "temporal wave-front tiling", параметр -bt
#   [5] Intel iso3dfd walkthrough — "b1 b2 b3: cache block sizes"
#
# ============================================================================

## 2. Сборка и запуск

### Сборка

```bash
source /opt/intel/oneapi/setvars.sh
rm -rf build
cmake -S . -B build -DVERIFY_RESULTS=0
cmake --build build -j$(nproc)
```

### Аргументы командной строки

```
./iso3dfd n1 n2 n3 b1 b2 b3 niter [mode]
```

| Параметр | Описание | Пример |
|----------|----------|--------|
| n1, n2, n3 | Размеры сетки (n3 делится по Z между рангами) | 256 256 256 |
| b1, b2, b3 | Размеры блока spatial tiling | 64 64 64 |
| niter | Количество итераций по времени | 2000 |
| mode | Режим выполнения (8-й аргумент) | pure_omp |

### Переменные окружения для temporal blocking

| Переменная | Описание | По умолчанию | Пример |
|------------|----------|--------------|--------|
| `ISO3DFD_TB_STEPS` | Число временных шагов в волновом фронте (N) | 0 (выкл.) | `ISO3DFD_TB_STEPS=4` |
| `ISO3DFD_B2_L2` | Размер L2-микроблока по Y (nested spatial tiling) | авто (48) | `ISO3DFD_B2_L2=48` |

### Режимы

| Режим | MPI рангов | OMP потоков | TB (N) | Команда |
|-------|-----------|-------------|---------|---------|
| `sequential` | 1 | 1 | 0 | `./build/iso3dfd 256 256 256 64 64 64 100 sequential` |
| `pure_mpi` | N | 1 | 0/4/8 | `mpirun -n 12 ./build/iso3dfd 256 256 480 64 64 64 2000 pure_mpi` |
| `hybrid` | M | T | 0/4/8 | `OMP_NUM_THREADS=6 mpirun -n 2 ./build/iso3dfd 256 256 480 64 64 128 2000 hybrid` |
| `pure_omp` | 1 | N | 0/4/8 | `OMP_NUM_THREADS=12 ISO3DFD_TB_STEPS=4 ./build/iso3dfd 256 256 256 64 64 64 2000 pure_omp` |

### Ограничения temporal blocking

- **N=0** — temporal blocking выключен, код работает как раньше (N=1, один шаг за вызов).
- **N>0** — требуется `b3 ≥ 8N + 64` (8N слоёв на wave-front + минимум 64 на вычисление).
- **N=4, b3=64** — минимальная конфигурация (8×4=32 halo + 32 interior = 64). Работает, но блок «тощий».
- **N=8, b3=128** — комфортная конфигурация (8×8=64 halo + 64 interior = 128).
- **n3 должно делиться на b3** (и на nprocs для MPI-режимов).


## 3. Блоки (слои кода)

### БЛОК 1: GRID (Сетка)

**Файлы:** `iso3dfd_grid.hpp` / `iso3dfd_grid.cpp`

**Ответственность:**
- Аллокация 3D-массивов с выравниванием 64 байта (`posix_memalign`)
- First-touch NUMA-политика (инициализация нулями на домене вызывающего потока)
- Инициализация данных: волновой импульс в центре, поле скоростей, коэффициенты стенсиля
- Хранение размеров (n1, n2, n3 + halo kHalfLength с каждой стороны)
- **НОВОЕ:** при `tb_steps > 0` — аллокация буфера на `kHalfLength * tb_steps` слоёв вместо `kHalfLength`
- Доступ по линейному индексу: `ptr[k * nx * ny + j * nx + i]`
- Освобождение памяти
- Верификация результата (NaN/Inf — при `VERIFY_RESULTS=1`)

**НЕ знает про:** MPI, OpenMP, режимы, стенсиль. Просто данные.

---

### БЛОК 2: SOLVER (Решатель — вычислительное ядро)

**Файлы:** `iso3dfd_solver.hpp` / `iso3dfd_solver.cpp`

**Ответственность:**
- Вычисление одной точки стенсиля 16-го порядка (49 точек, 9 коэффициентов, 63 FLOP/точка)
- Одна итерация: чтение `prev` → запись `next`
- Переключение: `compute_serial` (1 поток) или `compute_omp` (OpenMP)
- **Spatial tiling** (L3-блок): блоки (b1, b2, b3) переиспользуют данные в L3
- **Nested spatial tiling** (L2-микроблок): подблок b2_l2 внутри L3-блока, переиспользует в L2
- **НОВОЕ: Temporal tiling** (волновой фронт): `compute_temporal_block()` — N шагов по времени внутри одного L3-блока
- Обработка внутренних границ домена (kHalfLength отступ от краёв)

**НЕ знает про:** MPI, декомпозицию домена, halo exchange. Работает с локальным куском Grid.

**Три пути вычисления (после внедрения TB):**
- `compute_serial()` — линейный обход, 1 шаг (N=0, без temporal blocking)
- `compute_omp()` — `#pragma omp parallel for` по Z и Y, двухуровневое блокирование, 1 шаг (N=0)
- `compute_temporal_block()` — **НОВОЕ:** wave-front по (Z, T), N шагов, L3-resident (N>0)

**Структура temporal tiling внутри `compute_temporal_block()`:**

```text
compute_temporal_block(prev, next, block_z_start, block_z_end, N)
│
├── Spatial tiling: внешний цикл по L3-блокам (b1=64, b2=64, b3=64–128)
│   │
│   └── Wave-front по времени: для каждого z-диапазона
│       │
│       ├── T=0: вычислить z-слой из prev → next
│       ├── T=1: вычислить z+8 слой из next → prev  (сдвиг на kHalfLength)
│       ├── T=2: вычислить z+16 слой из prev → next
│       ├── ...
│       └── T=N-1: последний слой
│           │
│           └── Nested spatial tiling: внутри каждого T-шага
│               │
│               └── L2-микроблок (b2_l2=48): цикл по Y с шагом 48
│                   │
│                   └── L1-векторизация: цикл по X (64 элемента, 16 SSE-векторов)
```

---

### БЛОК 3: DRIVER (Делитель/Драйвер — оркестрация)

**Файлы:** `iso3dfd_driver.hpp` / `iso3dfd_driver.cpp`

**Ответственность:**
- Декомпозиция домена: разрез по Z (n3 / nprocs слоёв на ранг)
- Halo exchange: `MPI_Sendrecv` между соседями по Z
- **НОВОЕ:** при `tb_steps > 0` — расширенный halo exchange: `8N` слоёв вместо `8`
- Временной цикл: niter итераций (при TB — niter/N макро-итераций, каждая с N внутренними шагами)
- Передача управления в Solver на каждой итерации (или макро-итерации)
- Смена буферов prev <-> next (обмен указателей, без копирования)
- Тайминг: wall time, GFLOPS, lattice points/iteration

**Поведение по режимам (с temporal blocking):**
- `sequential` / `pure_omp` — nprocs=1, нет MPI, нет halo exchange. TB работает внутри Solver.
- `pure_mpi` — nprocs=N, `use_omp=false`, `MPI_Sendrecv` расширенного halo (8N слоёв) каждые N шагов.
- `hybrid` — nprocs=M, `use_omp=true`, `MPI_Sendrecv` расширенного halo (8N слоёв) + OpenMP внутри.

**Ключевое изменение в Driver при TB:**

Без TB (N=0):
```
на каждой итерации t:
  exchange_halo(8 слоёв)
  compute_iteration(prev → next)  // 1 шаг
  swap(prev, next)
```

С TB (N=4):
```
каждые N итераций (t, t+1, t+2, t+3):
  exchange_halo(8×4=32 слоёв)     // один расширенный обмен на N шагов
  compute_temporal_block(prev → next, N=4)  // 4 шага в L3
  swap(prev, next)
```


## 4. Матрица: 4 режима × 3 блока (с temporal blocking)

| Режим | GRID | SOLVER | DRIVER |
|-------|------|--------|--------|
| **SEQUENTIAL** (1 proc, 1 thread) | Полная сетка + halo 8N | `compute_serial` (N=0) или `compute_temporal_block` (N>0) | Нет MPI, 1 ранг, 1 поток |
| **PURE_MPI** (N procs, 1 thread) | Кусок + halo 8N | `compute_serial` (N=0) или `compute_temporal_block` (N>0) | `MPI_Sendrecv` 8N слоёв, N рангов |
| **HYBRID** (M procs, T threads) | Кусок + halo 8N | `compute_omp` (N=0) или `compute_temporal_block` (N>0) | `MPI_Sendrecv` 8N слоёв + OpenMP |
| **PURE_OMP** (1 proc, N threads) | Полная сетка + halo 8N | `compute_omp` (N=0) или `compute_temporal_block` (N>0) | Нет MPI, 1 ранг, N потоков |


## 5. Уровни параллелизма (снизу вверх)

| Уровень | Механизм | Режимы | temporal blocking |
|---------|----------|--------|-------------------|
| 1. SIMD/Векторный | Авто-векторизация icpx (-xSSE4.2) | Все | Внутренний цикл по X, 16 SSE-векторов |
| 2. Многопоточный | OpenMP (`#pragma omp parallel for`) | HYBRID, PURE_OMP | Параллелизм по L3-блокам |
| 3. Внутриузловой | MPI между рангами на одном сокете | PURE_MPI, HYBRID | Расширенный halo 8N |
| 4. Межузловой | MPI между серверами | PURE_MPI, HYBRID | Расширенный halo 8N |
| **5. Temporal** | **Wave-front по (Z,T)** — **НОВОЕ** | **Все (N>0)** | **N шагов в L3-resident блоке** |

```
SEQUENTIAL:  уровень 1 (+ 5 при N>0)
PURE_MPI:    уровни 1 + 3/4 (+ 5 при N>0)
HYBRID:      уровни 1 + 2 + 3/4 (+ 5 при N>0)
PURE_OMP:    уровни 1 + 2 (+ 5 при N>0)
```


## 6. Поток данных в одной итерации

### 6.1. Без temporal blocking (N=0) — текущий код

```
  DRIVER                         SOLVER                      GRID
  -------                        ------                      ----

  +------------------+
  | 1. Halo exchange |------------------------------------>  prev (halo: 8 слоёв обновлены)
  |  (MPI_Sendrecv)  |
  +--------+---------+
           |
           v
  +------------------+    +----------------------+
  | 2. Call Solver   |--->| compute_iteration()  |-->  read  prev[i±8, j±8, k±8]
  |  (mode-aware)    |    |  serial or OMP       |      write next[i, j, k]
  |                  |    |                      |      (1 шаг по времени)
  +--------+---------+    +----------+-----------+
           |                         |
           v                         v
  +------------------+                       prev <--> next (swap указателей)
  | 3. Swap prev/next|--------------------------------->  pointer swap
  +--------+---------+
           |
           v
  +------------------+
  | 4. Timing/Output |
  +------------------+
```

**Описание шагов (N=0):**

1. **Halo exchange** — Driver отправляет/принимает `kHalfLength=8` слоёв по Z соседним рангам через `MPI_Sendrecv`. В режимах `sequential` и `pure_omp` (nprocs=1) — пропускается. Объём MPI: `2 × 8 × 256 × 256 × 4 = 4 МБ` на итерацию.

2. **Call Solver** — Driver вызывает `compute_iteration(prev, next, ..., use_omp)`. Один шаг стенсила: 49 загрузок, 1 запись, 63 FLOP на точку. L3-блок 64×64×64, L2-микроблок b2_l2=48. Данные: `prev` → читается из L3/L2/L1 (по Layer Condition), `next` → пишется.

3. **Swap** — обмен указателей `prev ↔ next` без копирования. O(1).

4. **Timing** — Driver фиксирует время, считает GFLOPS.

**AI = 0.42 FLOP/byte (memory-bound). DRAM-трафик: ~150 Б/точка.**

---

### 6.2. С temporal blocking (N=4) — планируемый код

```
  DRIVER                         SOLVER                         GRID
  -------                        ------                         ----

  +---------------------+
  | 1. Расширенный halo |------------------------------------->  prev (halo: 8×4=32 слоёв)
  |    MPI_Sendrecv      |                                     next (halo: 32 слоёв)
  |    (8N = 32 слоёв)   |
  +--------+------------+
           |
           v
  +---------------------+    +----------------------------+
  | 2. Call Solver TB   |--->| compute_temporal_block()    |
  |    (N=4, mode-aware)|    |                             |
  |                     |    |  Wave-front по (Z, T):      |
  |                     |    |                             |
  |                     |    |  T=0: prev[z]   → next[z+0]  |---> read  prev[k±8]
  |                     |    |       (Z-stream 8 слоёв)    |     write next[k]
  |                     |    |                             |
  |                     |    |  T=1: next[z+8] → prev[z+8]  |---> read  next[k±8]
  |                     |    |       (Z-stream 8 слоёв)    |     write prev[k]
  |                     |    |                             |
  |                     |    |  T=2: prev[z+16]→ next[z+16]|---> read  prev[k±8]
  |                     |    |       (Z-stream 8 слоёв)    |     write next[k]
  |                     |    |                             |
  |                     |    |  T=3: next[z+24]→ prev[z+24]|---> read  next[k±8]
  |                     |    |       (Z-stream 8 слоёв)    |     write prev[k]
  |                     |    |                             |
  |                     |    |  Каждый T-шаг:               |
  |                     |    |    Spatial tiling (64×64×b3)  |
  |                     |    |    → Nested spatial (b2_l2)   |
  |                     |    |    → L1-векторизация (64×4)   |
  |                     |    +--------------+--------------+
  +--------+------------+                   |
           |                                v
  +---------------------+            Все N=4 шага выполнены
  | 3. Swap prev/next   |--->       в L3-resident блоке.
  |    (один swap на N  |            Данные не уходили в DRAM
  |     шагов)          |            между T-шагами.
  +--------+------------+
           |
           v
  +---------------------+
  | 4. Timing/Output    |
  +---------------------+
```

**Описание шагов (N=4):**

1. **Расширенный halo exchange** — Driver отправляет/принимает `8 × N = 32` слоя по Z (вместо 8). Объём MPI: `2 × 32 × 256 × 256 × 4 = 16 МБ` — один обмен на 4 итерации (вместо 4 обменов по 4 МБ = 16 МБ). **Суммарный MPI-трафик не меняется**, но число вызовов `MPI_Sendrecv` сокращается в N раз.

2. **Temporal tiling в Solver** — `compute_temporal_block()` выполняет N=4 шага стенсила внутри одного L3-блока, не выходя в DRAM между шагами:
   - **T=0:** вычисляет z-слой из `prev`, пишет в `next`. Z-streaming: 8 слоёв от `prev` загружены в L2/L1, результат — в `next`.
   - **T=1:** сдвиг на 8 по Z. Читает из `next` (уже в L3 от T=0!), пишет в `prev`. **Ключевой момент:** `next`-данные от T=0 всё ещё в L3 — переиспользование!
   - **T=2:** ещё сдвиг на 8. Читает из `prev` (от T=1, в L3), пишет в `next`.
   - **T=3:** финальный сдвиг. Читает из `next` (от T=2), пишет в `prev`.
   - После T=3: результат в `prev` (или `next` — зависит от чётности N). Swap указателей.

3. **Swap** — один обмен `prev ↔ next` на N шагов (вместо N обменов). O(1).

4. **Timing** — Driver считает GFLOPS по факту N шагов.

**Рабочий набор в L3 на один T-шаг (6 потоков):**
- `24 z-плоскости × 64 × 64 × 4 = 384 КБ/поток`
- `6 потоков × 384 КБ = 2,3 МБ < 10,5 МБ эффективного L3` (запас 78%)

**AI при N=4: `0,42 × 4 = 1,68 FLOP/byte`** — в 4 раза выше, чем без TB.
**DRAM-трафик: `~37 Б/точка`** — в 4 раза меньше, чем без TB.

### 6.3. Сравнение потоков данных: N=0 vs N=4

| Параметр | N=0 (без TB) | N=4 (с TB) |
|----------|-------------|------------|
| Halo exchange за итерацию | 8 слоёв, каждый шаг | 32 слоя, раз в 4 шага |
| MPI-объём на макро-итерацию | 4 × 4 МБ = 16 МБ | 1 × 16 МБ = 16 МБ |
| Вычислений на макро-итерацию | 4 шага × 63 FLOP | 4 шага × 63 FLOP |
| DRAM-трафик на точку | ~150 Б | ~37 Б |

| Рабочий набор в L3 | 272 КБ (1 z-плоскость × 17) | 384 КБ (24 z-плоскости) |
| L3-запас (6 потоков) | 98% | 78% |
| Узкое место | DRAM bandwidth | compute (при N≥8) |
| Прогноз GFLOPS | ~17 | 50–70 (N=4), 80–100 (N=8) |

### 6.4. Схема wave-front в (Z, T) пространстве

```
Z-координата →
              z₀  z₁  z₂  z₃  z₄  z₅  z₆  z₇  z₈  z₉  z₁₀ z₁₁ z₁₂ ...
              
T=0:          ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ...
              └─── kHalfLength=8 слоёв зависимости ──┘
T=1:              ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ...
                  └─── сдвиг на 8 ───────────────┘
T=2:                  ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ...
                      └─── сдвиг на 8 ───────────┘
T=3:                      ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   ...
                          └─── сдвиг на 8 ───────┘

Каждый шаг T сдвигается на kHalfLength=8 позиций по Z.
■ — вычисляемая z-плоскость
Между T-шагами данные НЕ уходят в DRAM — они в L3.
Размер рабочей области в Z: N × 8 + b3.
```

Для N=4, b3=64: рабочая область = 4×8 + 64 = 96 z-плоскостей.
Для N=8, b3=128: рабочая область = 8×8 + 128 = 192 z-плоскостей.


## 7. Карта взаимодействия модулей (с temporal blocking)

### 7.1. Без TB (N=0) — текущий код

```
MAIN (iso3dfd.cpp)
  +-- Парсинг аргументов: n1 n2 n3 b1 b2 b3 niter [mode]
  +-- MPI_Init / MPI_Comm_rank / MPI_Comm_size
  +-- Allocate (GRID) — halo = kHalfLength = 8
  +-- Initialize (GRID)
  +-- run_driver() (DRIVER)
        |
        +-- Цикл по итерациям (niter)
        |   +-- exchange_halo() -> MPI_Sendrecv (8 слоёв)
        |   +-- compute_iteration()  --> SOLVER
        |   |   +-- use_omp=false -> compute_serial()
        |   |   +-- use_omp=true  -> compute_omp()
        |   |       +-- Spatial tiling: L3-блок (b1, b2, b3)
        |   |       +-- Nested spatial tiling: L2-микроблок (b2_l2)
        |   |       +-- Векторизация: цикл по X (16 SSE-векторов)
        |   +-- swap(prev, next)      --> GRID
        |
        +-- PrintSummary()  --> GRID
```

### 7.2. С TB (N>0) — планируемый код

```
MAIN (iso3dfd.cpp)
  +-- Парсинг аргументов: n1 n2 n3 b1 b2 b3 niter [mode]
  +-- Чтение ISO3DFD_TB_STEPS из окружения (НОВОЕ)
  +-- MPI_Init / MPI_Comm_rank / MPI_Comm_size
  +-- Allocate (GRID) — halo = kHalfLength × max(1, tb_steps) (НОВОЕ)
  +-- Initialize (GRID)
  +-- run_driver() (DRIVER)
        |
        +-- tb_steps == 0 → обычный цикл (см. 7.1)
        |
        +-- tb_steps > 0 → цикл по макро-итерациям (niter / tb_steps)
        |   +-- exchange_halo() -> MPI_Sendrecv (8 × tb_steps слоёв) (НОВОЕ)
        |   +-- compute_temporal_block()  --> SOLVER (НОВОЕ)
        |   |   +-- Wave-front по (Z, T):
        |   |   |   +-- T=0: compute_iteration(prev → next)
        |   |   |   +-- T=1: compute_iteration(next → prev)  // L3-resident!
        |   |   |   +-- T=2: compute_iteration(prev → next)
        |   |   |   +-- ... (N шагов)
        |   |   |   +-- Каждый шаг:
        |   |   |       +-- Spatial tiling: L3-блок (b1, b2, b3)
        |   |   |       +-- Nested spatial tiling: L2-микроблок (b2_l2)
        |   |   |       +-- Векторизация: цикл по X
        |   |   +-- swap(prev, next) // один swap на N шагов
        |   +-- swap(prev, next)      --> GRID
        |
        +-- PrintSummary()  --> GRID
```


## 8. Иерархия тайлинга — детальная схема

```text
┌─────────────────────────────────────────────────────────────┐
│  Domain: 256 × 256 × 256 (или 256 × 256 × 480)              │
│  MPI-декомпозиция: по Z (n3 / nprocs)                        │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  L3-блок (Spatial tiling): 64 × 64 × b3              │  │
│  │  Бюджет L3: 1,75 МБ/поток (12 МБ / 6 + коррекция)     │  │
│  │  Рабочий набор: 272 КБ (N=0) ... 384 КБ (N=4)         │  │
│  │                                                       │  │
│  │  ┌─────────────────────────────────────────────────┐  │  │
│  │  │  Temporal tiling: N=4 шага по времени          │  │  │
│  │  │  (Wave-front, сдвиг 8 слоёв по Z на шаг T)      │  │  │
│  │  │  Рабочий набор: (16+N) × 64 × 64 × 4 байт       │  │  │
│  │  │  N=4: 384 КБ/поток << 1,75 МБ (запас 78%)       │  │  │
│  │  │                                                 │  │  │
│  │  │  ┌───────────────────────────────────────────┐  │  │  │
│  │  │  │  L2-микроблок (Nested spatial tiling):    │  │  │  │
│  │  │  │  64 × 48 (b1 × b2_l2)                    │  │  │  │
│  │  │  │  Бюджет L2: 256 КБ, занято: 204 КБ (80%)  │  │  │  │
│  │  │  │                                           │  │  │  │
│  │  │  │  ┌─────────────────────────────────────┐  │  │  │  │
│  │  │  │  │  L1-векторизация:                  │  │  │  │  │
│  │  │  │  │  Цикл по X: 64 элемента            │  │  │  │  │
│  │  │  │  │  16 SSE4.2-векторов (4 float/вект) │  │  │  │  │
│  │  │  │  │  Бюджет L1: 32 КБ, занято: ~1 КБ   │  │  │  │  │
│  │  │  │  └─────────────────────────────────────┘  │  │  │  │
│  │  │  └───────────────────────────────────────────┘  │  │  │
│  │  └─────────────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### Параметры тайлинга по уровням

| Уровень | Параметр | Значение | Кэш | Запас | Источник |
|---------|----------|----------|-----|-------|---------|
| Spatial tiling | b1, b2, b3 | 64, 64, 64–128 | L3 (12 МБ) | 78–98% | Аргументы запуска |
| Temporal tiling | tb_steps (N) | 4 (этап 1), 8 (этап 2) | L3 | 78% (N=4) | `ISO3DFD_TB_STEPS` env |
| Nested spatial | b2_l2 | 48 | L2 (256 КБ) | 20% | `ISO3DFD_B2_L2` env |
| Векторизация | — (авто) | 64 × 4 байт | L1 (32 КБ) | 97% | icpx `-xSSE4.2` |


## 9. Стратегия внедрения по этапам

### Этап 1: Proof-of-concept (b3=64, N=4)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| b3 | 64 | Без изменения — текущий размер блока |
| N (tb_steps) | 4 | Минимум: 8×4=32 halo + 32 interior = 64 |
| b2_l2 | 48 | Текущий оптимум (подтверждён tuning) |
| Рабочий набор | 384 КБ/поток | (16+4)×64×64×4 = 384 КБ |
| L3-запас | 78% | 2,3 МБ < 10,5 МБ (6 потоков) |
| AI | 1,68 | 0,42 × 4 |
| DRAM-трафик | ~37 Б/точка | В 4 раза меньше текущего |
| Прогноз GFLOPS | 50–70 | Утилизация 34–48% от SSE4.2 peak (147) |
| Ускорение | 3–4× | Относительно текущих ~17 GFLOPS |

**Объём кода:** ~100 строк (без расширения b3).
**Риск:** b3=64 при N=4 — блок «тощий» (32 interior), возможны накладные расходы на управление wave-front.

### Этап 2: Полный прорыв (b3=128, N=8)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| b3 | 128 | Увеличение для N=8: 8×8=64 halo + 64 interior |
| N (tb_steps) | 8 | Комфортный максимум для L3 Westmere |
| b2_l2 | 48 | Без изменения |
| Рабочий набор | 576 КБ/поток | (16+8)×64×64×4 = 576 КБ |
| L3-запас | 71% | 3,46 МБ < 10,5 МБ (6 потоков) |
| AI | 3,36 | 0,42 × 8 |
| DRAM-трафик | ~19 Б/точка | В 8 раз меньше текущего |
| Прогноз GFLOPS | 80–100 | Утилизация 55–68% от SSE4.2 peak |
| Ускорение | 5–6× | Относительно текущих ~17 GFLOPS |

**Объём кода:** ~30 дополнительных строк (расширение halo + тесты).
**Риск:** b3=128 требует `n3 % 128 == 0` и `n3 / nprocs % 128 == 0`.

### Этап 3 (резерв): L2 temporal blocking (48×48, N=8)

Если L3-latency (40 циклов) окажется критичной — переход на L2-resident блок 48×48:
- 2D LC в L2: 153 КБ < 256 КБ ✅
- N=8: 221 КБ < 256 КБ ✅ (запас 14%)
- AI = 3,68 (чуть выше L3 TB)
- Но: 31% частичных блоков (256/48 не делится нацело)
- И: 12 SSE-векторов вместо 16 (на 25% меньше)


## 10. Бенчмарк-план для temporal blocking

### Скрипт ISO3DFD_TB.sh

```bash
#!/bin/bash
# Перебор tb_steps: 0 (выкл), 1, 2, 4
# Сетка: 256×256×256, 2000 итераций, pure_omp 12, блок 64×64×64

for TB in 0 1 2 4; do
  echo ">>> tb_steps=$TB"
  if [ $TB -eq 0 ]; then
    OMP_NUM_THREADS=12 OMP_PROC_BIND=close OMP_PLACES=cores \
      ./build/iso3dfd 256 256 256 64 64 64 2000 pure_omp
  else
    OMP_NUM_THREADS=12 OMP_PROC_BIND=close OMP_PLACES=cores \
      ISO3DFD_TB_STEPS=$TB \
      ./build/iso3dfd 256 256 256 64 64 64 2000 pure_omp
  fi
done
```
