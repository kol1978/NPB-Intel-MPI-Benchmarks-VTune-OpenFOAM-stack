# Дополнение к разделу 5: Tuning b2_l2 — повторная серия (28 сентября 2026 г.)

## 5.6. Повторный tuning b2_l2 — две серии (28 сентября 2026 г.)

### Методология

- **Сервер:** kol-serv (Intel Xeon X5675, 2 × 6 ядер, 3.07 GHz)
- **Компилятор:** icpx (IntelLLVM 2026.1.1), `-O3 -fiopenmp -xSSE4.2`
- **Тест:** `pure_omp 12`, сетка 256×256×256, блок 64×64×64, 2000 итераций
- **Параметр:** `ISO3DFD_B2_L2` = 32, 40, 48, 56, 64
- **Окружение:** `OMP_NUM_THREADS=12`, `OMP_PROC_BIND=close`, `OMP_PLACES=cores`
- **Серии:** два полных прогона (09:02 и 09:25) для оценки воспроизводимости

### Анализ формы кривой

```
GFLOPS
 13.1 |·48····                    ← 27.09: пик на 48
 12.8 |     ·56·64                ← 28.09 серия 2: плато 48–64
 12.5 |········48·56              ← 28.09 среднее: пик 48–56
 12.0 |    ·40        ·64         ← 28.09 серия 1: пик на 48
 10.6 |·32                        ← все серии: провал на 32
      └──┴──┴──┴──┴──┴── b2_l2
        32  40  48  56  64
```

**Ключевые наблюдения:**

1. **b2_l2=32 — стабильно худший** во всех трёх сериях (10.54–13.00). Недоиспользование L2: 2D LC = 136 КБ при бюджете 256 КБ — слишком малый блок, накладные расходы на управление микроблоками доминируют.

2. **b2_l2=48–56 — оптимальный диапазон.** В серии 2 (09:25) b2_l2=56 даёт 12.80 GFLOPS — максимальный результат 28 сентября. В серии 1 пик на 48. Среднее по двум сериям: 48 и 56 идентичны (12.46).

3. **b2_l2=64 — не деградирует.** Вопреки ожиданиям (2D LC = 272 КБ > 256 КБ L2), производительность при 64 не падает: 12.40 (среднее), 12.78 (серия 2). Разница от оптимума — 0.5%, в пределах погрешности. Это указывает на то, что **L2-capacity не является узким местом** — код memory-bound, лимитирован пропускной способностью DRAM, а не вместимостью L2.

4. **Плато 48–64.** Во второй серии разброс между 48, 56 и 64 — 0.09 GFLOPS (0.7%). Это не шум — это плато: начиная с b2_l2=48, L2-подблок достаточно велик для эффективного Z-streaming, и дальнейшее увеличение не даёт ни выигрыша, ни проигрыша.

### Обновлённый вывод по b2_l2

| Критерий | b2_l2=48 | b2_l2=56 |
|----------|---------|---------|
| Среднее по 2 сериям (28.09) | 12.46 | 12.46 |
| Лучший одиночный результат | 12.71 | 12.80 |
| 2D LC в L2 | 204 КБ ✅ (запас 20%) | 238 КБ ✅ (запас 7%) |
| Стабильность между сериями | ±2.1% | ±2.8% |
| Авто-выбор по формуле | ✅ ($\lfloor 256 \times 0.8 / (17 \times 64 \times 4) \rfloor = 48$) | — |

**Рекомендация:** оставить `b2_l2=48` по умолчанию. Значения 48–56 дают одинаковый результат в пределах погрешности. Значение 48 выбрано как оптимальное по трём критериям:
- совпадает с авто-выбором по формуле $b2\_l2 = \lfloor L_2 \times 0.8 / ((2k+1) \times b_1 \times 4) \rfloor$;
- имеет больший запас по L2 (20% против 7%);
- меньший разброс между сериями (±2.1% против ±2.8%).

**Новое наблюдение:** b2_l2=64 (выход за L2) не вызывает деградации. Это означает, что стратегия «2D LC в L2» даёт выигрыш по сравнению с b2_l2=32 (10.58 vs 12.46, +18%), но не является жёстким порогом — L2 работает как буфер, а не как уровень блокировки. Реальное узкое место — пропускная способность DRAM.
