# MPI-рефакторинг iso3dfd: декомпозиция области и гало-обмен

> Документ описывает рефакторинг примера `iso3dfd_omp_offload` для добавления
> гибридного параллелизма (MPI + OpenMP) по аналогии с OpenFOAM.
>
> Рефакторинг не меняет вычислительное ядро (стенсил 16-го порядка) —
> добавляется новый уровень параллелизма поверх существующего OpenMP.

---
Intel показывает уровни 1 и 3 (OpenMP и SYCL, без MPI). Ты добавил уровень 2 (MPI + OpenMP). Уровень 4 (MPI + SYCL) — это уже продакшен-сценарий, который в учебных примерах встречается крайне редко.
Готовой MPI-версии iso3dfd от Intel/IXPUG не существует в публичном доступе. Этот рефакторинг — фактически единственная реализация iso3dfd с MPI-декомпозицией, гало-обменом и верификацией через MPI_Gatherv, совместимая с oneAPI-стеком (Intel MPI, icpx, OpenMP). IXPUG-материалы полезны как референс для следующего шага — оптимизации OpenMP-ядра (векторизация, cache blocking, NUMA first-touch), но не для MPI.

## 1. Терминология

| Термин | Значение |
|---|---|
| **Рефакторинг** | Переработка кода без изменения внешнего поведения, с улучшением внутренней структуры |
| **Декомпозиция области** (Domain Decomposition) | Разделение 3D-сетки на подобласти по оси Z между MPI-рангами |
| **Гало-обмен** (Halo / Ghost Cell Exchange) | Обмен граничными слоями (kHalfLength плоскостей) между соседними рангами |
| **Гибридный параллелизм** (Hybrid Parallelism) | MPI между процессами + OpenMP внутри процесса |
| **Ранг** (Rank) | MPI-процесс, работающий над своей подобластью сетки |
| **Гало-область** (Halo / Ghost Cells) | kHalfLength слоёв ячеек, принимаемых от соседей — нужны для стенсила у границ |
| **RPATH** | Запись пути к библиотеке прямо в ELF-бинарник — гарантирует загрузку Intel MPI, а не системного OpenMPI |

## 2. Назначение рефакторинга

### Проблема

Оригинальный `iso3dfd_omp_offload` — чистое OpenMP-приложение. В коде нет
`#include <mpi.h>`, нет `MPI_Init`, нет обмена между рангами. Команда
`mpirun -n 12 ./iso3dfd ...` запускает 12 независимых копий, каждый процесс
считает полную сетку 256x256x256.

Последствия:

- VTune `-trace-mpi` бесполезен — нет MPI-вызовов для трассировки.
- APS (Intel Application Performance Snapshot) не показывает ничего — нет коммуникаций.
- Дисбаланс рангов = 0 (все делают одно и то же).
- Невозможно профилировать реальный HPC-сценарий: коммуникация vs вычисление.

### Решение

Добавить MPI-декомпозицию по оси Z (как в OpenFOAM `decomposePar`):

- Каждый ранг хранит свою подобласть + kHalfLength слоёв гало.
- Каждую итерацию ранги обмениваются гало-данными через `MPI_Isend / MPI_Irecv`.
- Синхронизация через `MPI_Waitall`.
- Сбор метрик через `MPI_Reduce`.
- Верификация через `MPI_Gatherv` — сбор интерьера на rank 0 и сравнение с последовательным эталоном.

Объём изменений: ~150 строк в `iso3dfd.cpp`, ~80 строк в `iso3dfd_verify.cpp`, ~20 строк в `utils.cpp`, ~15 строк в `CMakeLists.txt`.

## 3. Структура исходного кода до рефакторинга

| Элемент | Описание |
|---|---|
| Сетка | `n1 x n2 x n3`, хранится как 1D-массив: индекс `iz * n1*n2 + iy * n1 + ix` |
| Гало | `2 * kHalfLength` (= 16) ячеек по каждой размерности для краевых точек стенсила |
| Стенсил | 16-й порядок: для каждой точки нужны 8 соседей в каждом направлении X, Y, Z |
| Ядро | `Iso3dfdIteration(ptr_next, ptr_prev, ptr_vel, coeff, n1, n2, n3, ...)` |
| Параллелизм | Только `#pragma omp parallel for` внутри одного процесса |
| MPI | Отсутствует |

    int nprocs = 1;

4.3. Декомпозиция по оси Z
Было: все ранги используют полную сетку n1 x n2 x n3.

Стало: каждый ранг получает свою полосу по Z.

cpp
size_t n3_local, z_start_global, n3_alloc;
#ifdef USE_MPI
    n3_local = n3_user / nprocs;
    size_t remainder = n3_user % nprocs;
    if (rank < (int)remainder) n3_local++;
    z_start_global = rank * (n3_user / nprocs)
                   + std::min((size_t)rank, remainder);
    n3_alloc = n3_local + 2 * kHalfLength;
#else
    n3_local = n3_user;
    z_start_global = 0;
    n3_alloc = n3_user + 2 * kHalfLength;
#endif
n3_user — внутренний размер по Z (без halo), задаётся в аргументах командной строки.
n3_alloc — полный локальный размер массива: n3_local + 2 * kHalfLength (гало сверху и снизу).
z_start_global — глобальный индекс начала Z-слоя для данного ранга (используется при верификации).
4.4. Выделение памяти — локальные подобласти
Было:

cpp
size_t nsize = n1 * n2 * n3;
float *ptr_next = (float *)malloc(nsize * sizeof(float));
float *ptr_prev = (float *)malloc(nsize * sizeof(float));
float *ptr_vel  = (float *)malloc(nsize * sizeof(float));
Стало:

cpp
size_t total_size = n1 * n2 * n3_alloc;
float* prev_base = new float[total_size];
float* next_base = new float[total_size];
float* vel_base  = new float[total_size];
Каждый ранг выделяет память только под свою подобласть (n1 * n2 * n3_alloc).

Инициализация:

cpp
#ifdef USE_MPI
  InitializeLocal(prev_base, next_base, vel_base, n1, n2, n3_alloc,
                  z_start_global, n3_local, rank, nprocs);
#else
  Initialize(prev_base, next_base, vel_base, n1, n2, n3_alloc);
#endif
Initialize и InitializeLocal заполняют vel = 2250000.0f * dt * dt, prev = 1.0f, next = 0.0f.

4.5. Модификация вызова Iso3dfdIteration
Было:

cpp
Iso3dfdIteration(ptr_next, ptr_prev, ptr_vel, coeff, n1, n2, n3, ...);
Стало:

cpp
Iso3dfd(next_base, prev_base, vel_base, coeff,
        n1, n2, n3_alloc,           // локальный размер с гало
        n1_block, n2_block, n3_block,
        num_iterations
#ifdef USE_MPI
        , rank, nprocs
#endif
        );
Внутри Iso3dfd цикл по итерациям вызывает Iso3dfdIteration, передавая n3_alloc как размер по Z. Функция Iso3dfdIteration сама пропускает первые и последние kHalfLength слоёв (гало), начиная и заканчивая вычисления на внутренних точках:

cpp
size_t n3_end = n3 - kHalfLength;  // n3 = n3_alloc
size_t n2_end = n2 - kHalfLength;
size_t n1_end = n1 - kHalfLength;
Вычислительное ядро не меняется — только размер передаваемой области.

4.6. Гало-обмен между итерациями
Ключевой блок рефакторинга — аналог обмена граничными полями в OpenFOAM.

cpp
#ifdef USE_MPI
void ExchangeHaloZ(float* ptr, size_t n1, size_t n2, size_t n3_alloc,
                   int rank, int nprocs) {
  size_t layer_size = n1 * n2;
  size_t halo_size = kHalfLength * layer_size;

  MPI_Request requests[4];
  int req_count = 0;

  // Обмен с рангом сверху (rank + 1)
  if (rank < nprocs - 1) {
    float* send_buf = &ptr[(n3_alloc - 2 * kHalfLength) * layer_size];
    float* recv_buf = &ptr[(n3_alloc - kHalfLength) * layer_size];
    MPI_Isend(send_buf, halo_size, MPI_FLOAT, rank + 1, 0,
              MPI_COMM_WORLD, &requests[req_count++]);
    MPI_Irecv(recv_buf, halo_size, MPI_FLOAT, rank + 1, 1,
              MPI_COMM_WORLD, &requests[req_count++]);
  }

  // Обмен с рангом снизу (rank - 1)
  if (rank > 0) {
    float* send_buf = &ptr[kHalfLength * layer_size];
    float* recv_buf = &ptr[0];
    MPI_Isend(send_buf, halo_size, MPI_FLOAT, rank - 1, 1,
              MPI_COMM_WORLD, &requests[req_count++]);
    MPI_Irecv(recv_buf, halo_size, MPI_FLOAT, rank - 1, 0,
              MPI_COMM_WORLD, &requests[req_count++]);
  }

  if (req_count > 0) {
    MPI_Waitall(req_count, requests, MPI_STATUSES_IGNORE);
  }
}
#endif
Цикл по времени:

cpp
void Iso3dfd(float* ptr_next_base, float* ptr_prev_base, float* ptr_vel_base,
             float* coeff,
             size_t n1, size_t n2, size_t n3,
             size_t n1_block, size_t n2_block, size_t n3_block,
             size_t num_iterations
#ifdef USE_MPI
             , int rank, int nprocs
#endif
             ) {
  for (size_t iter = 0; iter < num_iterations; iter++) {
#ifdef USE_MPI
    ExchangeHaloZ(ptr_prev_base, n1, n2, n3, rank, nprocs);
#endif
    Iso3dfdIteration(ptr_next_base, ptr_prev_base, ptr_vel_base, coeff,
                     n1, n2, n3, n1_block, n2_block, n3_block);
    std::swap(ptr_prev_base, ptr_next_base);
  }
}
Логика обмена
text
Ранг 0          Ранг 1          Ранг 2
┌─────────┐    ┌─────────┐    ┌─────────┐
│ гало    │    │ гало    │    │ гало    │
│─────────│    │─────────│    │─────────│
│ данные  │──> │ данные  │──> │ данные  │
│         │    │         │    │         │
│─────────│    │─────────│    │─────────│
│ гало    │    │ гало    │    │ гало    │
└─────────┘    └─────────┘    └─────────┘
     <──          <──          <──
   снизу         снизу         снизу
send_up — последние kHalfLength вычисляемых слоёв (перед верхним гало).
recv_up — верхнее гало, заполняется данными от ранга rank + 1.
send_down — первые kHalfLength вычисляемых слоёв (после нижнего гало).
recv_down — нижнее гало, заполняется данными от ранга rank - 1.
Теги сообщений: 0 — отправка вверх / приём снизу, 1 — отправка вниз / приём сверху.

5. Изменения в CMakeLists.txt
Проблема: системный OpenMPI вместо Intel MPI
На системе может быть установлен OpenMPI (libmpi.so.40). Если просто линковать через find_package(MPI) или -lmpi, линкер может подхватить системную библиотеку. Это вызывает segfault при запуске через Intel MPI mpirun.

Решение: линковка по полному пути + RPATH
cmake
if(ENABLE_MPI)
    set(MPI_ROOT "/opt/intel/oneapi/mpi/latest")
    set(MPI_INCLUDE_DIR "
